# WhatsApp-бот для «Табель»

Отдельный маленький сервис: подключается к WhatsApp владельца (как второе
устройство — та же технология, что у WhatsApp Web) и по запросу от основного
приложения пишет сообщения в общий групповой чат. Работает независимо от
основного сайта на Vercel — ему нужен свой постоянно работающий сервер
(Vercel для такого не подходит, поэтому здесь используется Render).

Это не для самостоятельной настройки вручную — Клод разворачивает этот сервис
сам через подключённый Render-аккаунт. Этот README — справочная памятка на
случай, если что-то нужно будет посмотреть или поправить позже.

## Из чего состоит

- `index.js` — сам бот: подключение к WhatsApp + маленький HTTP-сервер с
  тремя ручками (`/qr`, `/groups`, `/notify`).
- `redis-auth-state.js` — хранит сессию WhatsApp в Redis (Render Key Value),
  а не на диске — иначе при каждом перезапуске сервиса пришлось бы заново
  сканировать QR-код.
- `package.json` — зависимости (Baileys — библиотека для подключения к
  WhatsApp, Express — веб-сервер, ioredis — клиент Redis).

## Переменные окружения

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | Секретный пароль для доступа к `/notify`, `/groups` и `/qr` — придумывается один раз при разворачивании, его же нужно прописать в основном приложении на Vercel как `WHATSAPP_BOT_TOKEN`. |
| `REDIS_URL` | Строка подключения к Render Key Value — Render подставляет её сам, если Key Value подключён к сервису. |
| `WHATSAPP_GROUP_ID` | ID нужного группового чата в WhatsApp — узнаётся уже после подключения через `/groups` (см. ниже), до этого можно оставить пустым. |
| `PORT` | Подставляется Render автоматически. |

## Разовая настройка после разворачивания

1. Открыть `https://<адрес-сервиса-на-render>/qr?token=<BOT_TOKEN>` в браузере
   на телефоне +996501720170.
2. В WhatsApp: Настройки → Связанные устройства → Привязать устройство →
   навести камеру на код на экране.
3. После успешного подключения страница `/qr` начнёт показывать «Уже
   подключено» вместо кода — это разовая операция, дальше сессия хранится в
   Redis и переживает перезапуски сервиса.
4. Открыть `https://<адрес-сервиса>/groups?token=<BOT_TOKEN>` — вернётся
   список всех групп, в которых состоит этот номер, с их `id` и названием.
   Найти нужный общий чат команды, скопировать его `id` (выглядит как
   `123456789-987654321@g.us`) и прописать как `WHATSAPP_GROUP_ID` в
   переменных окружения сервиса на Render, затем передеплоить.
5. Готово — основное приложение теперь может слать уведомления через
   `POST /notify` с телом `{"message": "текст"}` и заголовком
   `Authorization: Bearer <BOT_TOKEN>`.

## Если бот отвяжется

Если кто-то вручную отвяжет устройство в самом WhatsApp (или сессия истечёт),
бот сам это заметит, сбросит сохранённую сессию и на странице `/qr` снова
появится код — шаги 1–2 нужно будет повторить.

## Стоимость и задержка уведомлений

Бесплатный тариф Render "засыпает" после ~15 минут без запросов — первое
уведомление после паузы может прийти с задержкой в 20–60 секунд, пока сервис
просыпается и заново поднимает соединение с WhatsApp (сессия при этом не
теряется, только сам процесс). Если это неудобно и нужны уведомления вообще
без задержки — можно перевести сервис на платный тариф Render (~$7/мес,
сервис никогда не "спит").
