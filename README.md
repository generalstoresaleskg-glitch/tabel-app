# Табель — график работы и учёт времени

Внутренняя система для 3 точек уходовой косметики: составление и утверждение
недельного графика, отметки прихода/ухода/визита, табель и выгрузка в CSV
(промежуточная замена автоматической выгрузки в Google Sheets).

Полный согласованный план (роли, процессы, роадмап) — в файле `PLAN.md` в этом
репозитории и в проекте на claude.ai.

## Что уже реализовано (Этап 1 + часть Этапа 2)

- Роли и вход по логину/паролю: владелец, управляющая, сотрудник (RBAC на
  уровне страниц и серверных экшенов).
- Точки (филиалы): создание/редактирование/деактивация/удаление — только
  владелец.
- Сотрудники: создание и редактирование (управляющая может только рядовых
  сотрудников, роль меняет только владелец), смена пароля, деактивация.
- Владелец **не** участвует в графике как исполнитель — это заложено и на
  уровне интерфейса, и на уровне серверной проверки.
- Конструктор графика на неделю с двумя типами задач: обычная смена (SHIFT,
  время начала/конца) и визит-задача (VISIT, только точка + дата, для СММ).
- Цикл согласования: черновик → (владелец, только если черновик составляла
  управляющая) → публикация. Публикация не ждёт подтверждения от сотрудников —
  график сразу становится видимым всем.
- Правки уже опубликованного графика без повторного цикла согласования — с
  логом изменений (`schedule_change_log`).
- Отметки «Я на месте» / «Я ухожу» (с фиксацией опоздания/переработки) и
  «Посетила точку» для визит-задач.
- Табель: сводка по сотрудникам и детальный журнал по дням, с фильтром по
  месяцу. Экспорт в CSV (открывается в Google Sheets / Excel).

## Технологии

Next.js (App Router, Server Actions) + TypeScript + Tailwind CSS,
Drizzle ORM поверх Postgres (драйвер `@neondatabase/serverless`, оптимизирован
под serverless-хостинг вроде Vercel), NextAuth (Auth.js) v5 для логина по
паролю с ролями.

Задеплоенная версия использует Postgres через Neon (подключён к Vercel-проекту
как интеграция из Marketplace). Для локальной разработки подойдёт любой
Postgres — свой локальный сервер или тот же Neon (просто укажите его
`DATABASE_URL` в `.env.local`).

## Запуск локально

Понадобится доступ к любой Postgres-базе (локальной или облачной — например,
тот же бесплатный Neon).

```bash
npm install
cp .env.example .env.local
# впишите в .env.local свой AUTH_SECRET (команда для генерации — в самом файле)
# и DATABASE_URL — строку подключения к вашей Postgres-базе

npm run db:setup   # применяет миграции и заполняет базу тестовыми данными
npm run dev        # http://localhost:3000
```

## Структура проекта

```
src/
  app/
    login/                 страница входа
    points/                точки (владелец)
    employees/             сотрудники (владелец/управляющая)
    schedule/               график: конструктор, согласование, отметки
    tabel/                  табель + CSV-экспорт
  db/
    schema.ts               схема Drizzle (users, points, schedules, shifts, attendance, ...)
    seed.ts                  тестовые данные
  lib/
    session.ts               requireUser/requireRole
    dates.ts                  работа с неделями/месяцами
    notify.ts                 заглушка уведомлений (WhatsApp/Telegram)
    schedule-queries.ts        общие запросы к графику/табелю
tests/
  smoke-core.mjs             сквозной сценарий: владелец → график → сотрудник подтверждает
  smoke-extended.mjs         менеджер/СММ/отметки прихода-ухода/CSV
PLAN.md                       согласованный план проекта
```

## Прогон smoke-тестов

Тесты используют Playwright и предустановленный Chromium.

```bash
npm run db:setup   # чистая база
npm run dev &      # сервер на 3000
node tests/smoke-core.mjs
node tests/smoke-extended.mjs
```

## Деплой
